# 数据管理

数据库与 Geodata 是本机连接资产；配置格式见 [Xray 配置](xray-configuration.md)，备份范围见 [备份](backup.md)。

## 原库升级

当前数据库为 schema 9，支持已发布 v1–v8 的正式原位升级。结构修改与版本提交在同一事务中完成；
保留 ID、订阅关系、Base64 JSON、Age 密钥、HWID 和全部旧 Raw，包括超过新增上限的记录。
退休 Profile/full 行留在原库但不进入业务；旧产品模型按正式迁移转换结构，不重写 Raw 原文。
迁移移除节点出口地区列，为来源增加 panel/mode，旧来源默认为 generic/appManaged；
v1–v2 创建新结构时不新增退休地区列，v3–v6 删除已有列，历史套餐迁移只在 from<6 执行。
来源的可空 `userAgent` 仅用于单个订阅；未填写时使用统一的订阅默认 UA，自定义值优先，见 [订阅合同](subscriptions-and-sharing.md)。
手动分组独立存储名称与顺序，普通手动节点保存可空的分组引用和组内顺序；
未分组为虚拟分组，空自定义组保留。旧节点升级后归入未分组，同序时按 ID 保持原有次序，不改写配置原文。
未知连接选择 kind 在普通读取和运行 metadata 中统一回退 automatic，不为旧地区选择增加专门迁移或改写原文。
目标 GeoIP/Geosite、Smart 直连地区、Setup 地区与语言国家代码仍属于有效功能。
迁移不联网、不生成标识、不更新订阅，不在运行时复制全表验证或制作数据库快照。

`StoragePreparation` 在首次业务访问前打开数据库并完成迁移，不依赖 VPN 或 Setup。
不支持的版本、有业务表但版本为 0 的未知库直接拒绝；新文件或未完成创建的空库可以初始化。
打开失败释放连接，修复后可重试。App 不自动删库、降级或修补不兼容开发库。
迁移分支以 [数据库实现](../lib/core/db/database/database.dart) 为准；验证使用隔离样本，安装包升级另行验收。

## 数据订阅与队列

- UI 列表通过数据库 Stream 和页面 Cubit 更新，销毁页面时取消订阅；编辑草稿不被刷新覆盖。
  普通节点和提供方完整配置共用 [显示顺序](#数据显示顺序)，Raw 与订阅仍按 ID 排序。
  完整配置与普通派生缓存共用 CoreConfig，以 type/subId 区分；Raw 配额只计算个人 Raw，不限制订阅完整配置条数。
  当前 mode 统一过滤列表、连接候选、自动测速、最终出口与数量，模式不兼容的选择明确失败。
  单条编辑、后台任务及事务内读取使用一次性查询。
- 连接、Geodata 文件访问、测速各有独立 FIFO 队列，失败不阻断后续任务；不合并成全局队列。
  测速按提交顺序执行，多个订阅分批入队，同一订阅每批最多 5 个节点，批次结束后保存。
  自动测速在正常服务就绪后补测未检测节点；Setup 不导入节点、不启动或等待测速。
- 测速与下载分别发布到共享 `pinging` / `downloading`；并发下载计数归零才结束 loading。
  页面局部状态定位按钮和防重复提交，不替代共享状态，也不锁住整页。
- 普通保存、下载与测速不互相等待；名称、限额、原记录和来源在真正提交时复核。
  异步旧回包不能覆盖已修改、删除或替换的资产。VPN 状态与 metrics 读取不进入业务命令队列。

### 手动节点组织

仅普通手动节点参与自定义分组，订阅与个人 Raw 不改变归属。新导入与本地复制追加到未分组末尾，
移组仅更新归属与顺序，保留节点 ID、配置、收藏和延迟，不校验配置或重连。
解散分组将成员按原顺序追加至未分组；删除分组及节点复用节点删除预览与连接协调器，
确认后成员变化则中止，组和成员在同一事务删除。固定选择、最终出口及运行节点沿用既有删除处理。
清理与恢复先暂停分组写入并等待已准入事务，清理全部数据同步移除自定义组。

### 数据显示顺序

共享 `ServerCatalog` 为服务器浏览、最终出口选择和托盘提供同一顺序，不改写节点、来源或测速数据。
默认保留订阅节点的 ID 顺序与位置，手动节点按未分组、自定义组顺序和组内顺序排列，同序时按 ID 确定；
测速只更新原行状态，不触发位置变化。名称按实际显示名去除首尾空白并忽略大小写比较。
延迟排序先放成功结果并按耗时升序，再放未测、失败，最后为不参加普通测速的提供方完整配置；
同名、同延迟或同一非成功类别均按 ID 升序确定顺序。筛选只取子集，不重新排序，订阅分组次序不变。

名称、延迟等显示排序是设备偏好，保存后通过共享事件同步，重启沿用；缺失或未知值回到默认。
显示排序不改写手动顺序，切回默认时使用已保存的位置。手动分组和顺序进入资产备份，显示排序偏好不进入备份。
订阅刷新仍沿用正常替换与保护合同，新节点依据当前保存后的 ID/名称/延迟重新参与排序，
不维护跨刷新节点身份或手工位置。显示顺序与连接候选解析分离，自动接入仍按成功延迟、ID 选择，
已运行连接不随排序或测速更新迁移。偏好不进入备份；清理全部数据恢复默认顺序。

### 测速结果

手动与自动测速共用测速偏好，每个任务开始时读取一次 URL/超时，后续批次使用同一快照。
延迟是 HTTP HEAD 到响应头的耗时，`0` 是有效结果；每批最多五项，保留输入顺序与单项失败隔离。
不执行出口地区 GET、解析国家码或保存位置缓存，提供方完整配置不进入此队列。

结果按节点 ID、来源、类型与配置原文复核，来源切到提供方方式后不再测量或写回隐藏的普通派生行；
过期结果不能覆盖新资产。节点配置变更仍清理旧延迟。失败只保留进程内行提示，不保存错误历史。
手动确认和进程内错误提示见 [服务器页面](app.md#服务器)，自动流程不依赖页面确认。

订阅两类缓存的原子替换、运行/选择/收藏保护与模式切换见 [订阅合同](subscriptions-and-sharing.md#面板与配置使用方式)。
准备、待启动和运行引用包含完整配置 ID；来源删除同时清理两类缓存，按连接协调器处理正在使用的配置，
不能因完整配置的 entries 为空而漏掉引用。后台刷新不热替换当前会话。

## Geodata 发布

默认 `geoip.dat` / `geosite.dat` 是不可删除的一组，只能一起更新。
自定义来源支持 HTTPS 添加、更新和删除，不提供本地导入。`installed` 区分成功发布与备份恢复登记的待下载意图；
待下载行可没有文件，不显示伪造大小、时间或分类，成功下载后提交真实元数据。意外损坏不自动改成待下载。

`VpnConstants.datDir` 是唯一 App Geodata 读写目录，DAT、同名 JSON 索引及 `timestamp.txt` 平铺在根目录。
发布、移除和恢复保留文件名、保留名称、路径穿越与普通文件检查；暂存和局部恢复日志位于根目录的同级目录。

下载与 libXray DAT/索引验证在文件队列外进行，成功后才在文件队列内替换正式文件并提交数据库。
下载或验证失败不改旧文件；数据库失败回滚本次覆盖。默认组一起发布，自定义来源只覆盖自身。
旧文件缺失、为空或索引损坏不阻止有效新文件覆盖。生成索引只在同次受控暂存/发布中复用，不跨操作缓存有效性。

管理列表使用数据库计数、时间和文件元信息，不解析全量索引；详情只读取所选文件。
分类补全按已安装来源独立加载，缺失、不可读或格式错误的索引不提供分类，不使用示例补齐；
一个来源失败不阻断其他来源。管理和实际配置使用仍报告相关缺失/损坏错误，分享可使用待下载来源 URL。

Raw/Custom 导入只在同级暂存目录下载和验证，用户确认后由导入模块统一管理发布、保存与回滚。
文件队列覆盖正式发布到数据库提交，页面只持有配置草稿和依赖声明，不持有发布句柄。
取消清理本次暂存；失败回滚正式文件并保留可重试草稿；成功后不复用已完成事务。
冷启动按数据库 manifest 完成已提交发布或清理未提交文件。

备份恢复只复用同名、同类型、同 URL 且有效的自定义文件；预览只检查匹配候选，提交前重新核对冲突和复用事实。
受影响的旧文件移入局部日志，提交失败恢复；已缺失文件不阻止移除，非普通文件拒绝处理。
冷启动按记录 ID 判断回滚或清理，不复制 SQLite 或整个 App。

配置保存校验和实际启动直接使用平铺目录，准备/启动不复制、下载或更新文件，也不额外调用 `testXray`。
缺少必要文件明确失败，不联网兜底、不删规则或改直连。更新不重连，已运行 Core 继续使用启动时加载的规则。

macOS System Extension 因跨容器传输是唯一例外：清单纳入根目录普通文件，包括 Raw 证书，忽略子目录和符号链接。
非法根目录、已纳入文件读取失败、期望清单缺项/多项/时间不符均失败；完整空集合不同于未创建目录。
提交失败不发布半成品，按需启动只用最后完整目录；实际依赖由 Core 加载判断，不强制要求默认两份 DAT。
内部提交消息不兼容旧扩展，扩展未更新时明确失败，不建立另一套 App 资源目录。

### 冷启动重建

- 数据库本次启动前已丢失：旧文件失去 manifest，清理 orphan 并从内置资源重建默认组，不猜测自定义来源。
- 整个 dat 根目录缺失，或目录为空但仍有发布元数据：重建默认组，保留有意登记的待下载来源。
- 默认 DAT/索引缺失或为空：内置资源成组恢复并同步元数据，保留自定义来源与文件。
  默认文件和元数据齐全时不解析全部 DAT 或逐一验证索引。
- 无明确存储丢失信号时，额外文件和嵌套目录只忽略；自定义损坏不阻断启动，实际使用时报告错误。
  地区可跳过，没有分类时显示空列表，不阻止进入首页。

恢复不联网；丢失的自定义 manifest 或文件不能从默认资源找回。启动编排见 [App](app.md)。

## 自动更新

订阅与 Geodata 独立保存开关和 24/72/168 小时周期；所有订阅共用自动更新开关和周期，User-Agent 由各订阅单独管理。
启动、回前台、每小时和真实连接边沿检查到期；重复 connected 不重复调度。

订阅更新不要求 VPN；Geodata 自动更新仅在已确认连接时执行，连接成功后延迟 3 秒，期间断开则取消。
等待订阅更新后及每个 Geodata 来源开始前复核连接；断开不启动后续来源，已经开始的更新完成文件事务。
待下载来源直接视为到期；失败保留声明或旧文件，只记录更新错误，不改变 VPN、不重新选节点或重连。
手动更新和配置导入依赖下载不受自动更新的 VPN 条件限制。单源失败不长期阻断其他来源。

套餐只随订阅成功响应缓存，不另建请求或周期；[自动备份](backup.md#自动备份) 的开关、周期、时间和 VPN 条件均独立。

## 清理数据

`AppDataCleanupService` 只协调清理与备份恢复：先暂停接收相关模块新操作，再等待必要在途操作；
订阅导入不继续下一来源，测速完成当前原生批次后保存并取消后续请求，不等待全部排队测速。
取得 Geodata 文件队列后确认原生 VPN 停止，再替换数据；停止失败不继续删除，旧回包不能在替换后写回。
新连接命令在临界区拒绝，未开始命令取消，不在结束后自动执行旧保存/启动。成功或失败都恢复模块受理。

清理全部数据取消登录项、清空数据库/运行文件/用户偏好并重建默认资源，不重跑 Setup；
登录项取消失败在删除前停止，具体窗口与退出边界见 [App](app.md)。
备份恢复替换连接资产及匹配平台的 VPN 设置，保留本机绑定、授权和偏好，见 [备份](backup.md#恢复与缺失资源)。
两者都保留 Android 跨进程 START 准入保护，见 [外部接口](external-interfaces.md#设备授权与数据操作)。
清理移除本机备份绑定，不删除云文件。

平台验证与数据隔离遵循 [验证边界](validation.md)；真实旧安装包、文件中断恢复和 SE 传输/按需启动须在对应环境核对。
